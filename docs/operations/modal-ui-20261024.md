# モーダルUIとSite合成検証

ユーザー報告の入力例白文字は実際のSite合成画面でも再現した。`.prose form button`の白文字指定がtoolの一般buttonより優先され、sample専用styleが背景を透明にしていた。`button[type]`で前景と背景を一組にし、modalの外のform内にもsample canaryを置くSite回帰試験で確認する。

初回Library名検索では元画像IMG_8143.pngを解決できなかった。その後、ユーザーから渡された実際のfile参照を公式のmaterialization経路へ渡し、352065 bytesの原画像を取得してpixelsを確認した。旧previewの白文字と新規撮影・computed cascadeの再現も一致した。画像や署名URLは配布物へ含めない。

native dialog、適用前の設定下書き、取消、異常設定の不適用、入力のみの例、pending copy拒否後のfocus維持を対象テストへ加えた。WebKitのEscapeはkey送信直後にもdialogが開いている場合があり、閉鎖完了を待ってfocusを検査する。Site合成で結果見出しがhost fontを直接使うことも観測し、端末fontへ統一した。旧stage起動失敗はworkspace単独buildに_headersが含まれなかったもので、Site正規buildと従来headersのbyte一致を確認して再準備した。

最終headで全体test/check、2 clean build、配布物・Site検査、Firefox/WebKit、served hashと実画面を確認する。toolの通信ゼロとhostのfont requestを混同しない。実機iOS/Android、native IME・keyboard・paste、VoiceOver、BFCache、正式React採用は別の未検証範囲。push/merge/release/本番配信と既存統合保留の解除は行わない。
