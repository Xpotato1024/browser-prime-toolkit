# 承認された共通フローと入力制限表示

基準はローカル `550208e9180e7f0f0c381788dfcb61403d216ea1`。360専用実行を取り下げ、手入力／全入力例→共通実行→進行／結果の一つの流れにする。Site のヘッダーと本番配布物はこの変更に含めない。

入力欄の枠内に常時表示する上限は parser と engine の実際の境界に合わせる。通常は2^128未満（最大39桁、ただし全39桁の値ではない）、高精度／大メモリは最大100桁かつ332bit以下。先頭0を除いた正規化値で判定し、整数になる科学表記を受理する。元の表記は4096文字まで。maxlengthは使わず、超過を切り詰めず保持してエラーにする。BigIntによる全桁保持、既存の数値範囲、エンジン／Worker／WASM／予算の選択方針は変えない。

例の選択は入力のみ。一覧を閉じ、共通実行ボタンへfocusと表示位置を合わせる。開始操作時だけ進行／結果領域を表示し、完了時にスクロールしない。実行中の入力は読取専用で選択可能、設定は無効。取消完了とWorker解放を待ってから次の実行を受け付ける。

実行済み入力と結果は固定して表示する。入力または設定を編集したら未実行と明示し、旧結果は「前回」と示す。コピーはその結果の入力・確度・余因子・停止理由を保持する。実経過と設定上限、入力・設定・読込・実行のエラーを分ける。結果は通常の文章と式を先に表示し、全桁テキストの選択・判定理由・測定内訳は必要時に開ける。モバイルは一列、幅があるときは同じDOM順序の入力領域と進行／結果領域を横並びにできる。

対象テストは、正確な128/332bit境界、100桁でも332bit超過する値、4096/4097文字、先頭0、科学表記、小数、エラー分類、全入力例、編集後の前回結果、設定と実測の区別、読取専用・取消・再実行・コピー・focus・検証失敗後の新job識別を含む。独立レビューのP2で、検証エラー後にactiveJob snapshotが残る経路を修正し、再現テストを追加した。

ブラウザでは既存のPlaywright Coreを使いFirefoxとWebKitを順番に実行する。長い文字列はbulk text insertionで確認し、OS clipboardを使う物理的なpasteとは区別する。境界サイズの数値を因数分解する負荷試験はせず、純粋なvalidationで境界を確認する。Site のcanonical artifact checker、固定した同一headの全テスト・静的検査・2 clean build、実際のSite表示とHTTPプレビューは別の検証記録に保存する。

実iOS/Android、ソフトキーボード、読み上げソフト、BFCache、OS clipboard paste／許可画面は未検証。HTTPプレビューでは安全な接続を必要とするClipboard API等に制約があり、手動コピーへ切り替わる。確認ページは直接mountであり、正式React採用・v0.1.3・本番配信の検証とはしない。公開保留、releaseブランチへの統合制約、PR115/116除外を維持する。v0.1.2タグCI初回Native失敗・同一source再実行成功・原因未確定の履歴も保持する。
