# 小幅改善の反復選定と反映範囲

事前固定の2候補・8ブロック32試行を完了した。[全結果](../benchmarks/llm01-hotpath-repeat.md) と [契約](../contracts/hotpath-repeat.md) を参照。

境界係数1は時間比0.971954（約2.80%短縮）、prefix順変更は0.984192（約1.58%短縮）。両候補ともABBA/BAAB双方と全4ブロックで改善した。arm内CVは係数1がA0.69%/B0.38%、prefixがA0.25%/B0.22%。PSS比は1.000366と1.002064。小差を旧5%閾値だけで捨てず、今回の事前0.5%幅・参考上側値・順序・一貫性・メモリを満たすと判断した。ただし4個の連続blockの独立性・分布仮定には限界があり、他環境への確定的速度優位ではない。

## 費用評価と採否

境界係数2→1は一つの既存分岐境界だけを変え、追加配列・整数方式・新しい依存を持たない。prefixはループ構造の変更を伴い、今回は効果も小さかった。前者だけを選び、両候補の未検証の組合せを作らない。

選定済みwide入口は [契約](../contracts/selected-wide.md) に従う。64MiB helperと1024MiB ownerの両方へ同じ関数を反映し、ownerは実測したWASMを再利用する。通常UIと歴史的な64/128/256 artifactを変えず、明示入口を `src/selected-wide/index.js` とする。runnerは既存wideからfactory importと相対budget/memory参照だけを差し替えて生成し、挙動を分岐させない。Worker protocolもWASM定数以外は同一にする。生成物の保守費用はあるが、動作コードの分岐や入力別の新heuristicを増やさず約2.8%の限定的効果を反映できる。

新helperの機能同値とChrome契約は追加確認する。実測済みownerのNative40/64、oracle443、22共通Chrome契約と32試行を再利用し、同じ検査を無目的に積み増さない。[追加機能試験](../benchmarks/llm01-selected-wide.md) に測定headと実結果を記録する。

## 残る境界

今回の32試行はLLM-01・Chrome155・RSA100先頭4family・1Worker。全入力、後半family、5Worker全工程、別端末は未測定で、RSA100の37分を2.8%短縮すると予測しない。追加の長時間試行・新候補は0件。prefixは単体の改善証拠を保存するが今回は未採用。候補の合成、根更新・多項式準備の別案、端末間検証は今後の仮説であり、改善余地が枯渇したとは扱わない。

PR25を基準にした依存Draft PRへ保存する。merge/release/本番切替/サイト統合は行わない。最終レビューとCIは同じ最終headを確認する。

独立レビューで原本再生validatorが22件の総数と一部名称のみを検証するP2が見つかった。原本の成功は変わらず、正確な22名称の順序・全passを固定し、欠落・重複による件数補充・名称差替え・順序・失敗の負例を追加した。実red/greenをローカル保存し、既存実測やNativeを再実行せず検証器を修正した。
