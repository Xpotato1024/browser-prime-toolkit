# 案Aのローカル検証

対象は承認済みGUI候補のローカル修正とTailscale限定プレビュー。push・merge・release・正式Site採用・本番配信は含まない。PR115/116、資格情報、権限、CSP、監視設定は変更しない。

現行画面をdesktop WebKitで撮り直し、実行条件が結果より前、コピー用の重複結果欄、WASM予算と経路上限0 MiBの紛らわしさを確認した。小入力360はbrent経路でWASM線形メモリを使わず、128 MiBの設定予算と0の経路上限は異なる意味だった。表示を分離し、使用量を測ったとはしない。

新規の構造・IME確認・設定保持テストは変更前に失敗。独立レビューで見つかった隠し設定値・無効な手動予算の読み替え・キーを伴わないIME確定後のEnter抑止も回帰テストへ加えた。入力エラーを先に判定し、選択planを成立させてから小入力の経路planを決める。実ブラウザーは既存の別導入PlaywrightでFirefox/WebKitを順番に動かす。OS IME・実機iOSの試験とは区別する。最終headの集約test/check、2 clean build一致、Site artifact検査、限定プレビューの読戻しを別途記録する。

旧v0.1.2タグCIの初回Native validation失敗・同一ソース再実行成功・原因未確定という履歴は保持する。今回のGUI変更が原因を説明／解消したという扱いにはしない。正式v0.1.3の統合・公開に関する既存の未解決ゲートは維持する。
