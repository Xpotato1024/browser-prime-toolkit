# ADR0021: conservative automatic resources and explicit experimental settings

Accepted for private implementation and finite evaluation, not production integration.

A browser offers advisory device information and per-module WASM maxima, not reliable free RAM, CPU affinity or a whole-tab memory hardcap. Preserve exact BigInt arithmetic and the inexpensive ordinary route. An explicit experimental entry prepares fixed same-origin assets first and uses finite named resource profiles for heavier inputs.

Keep automatic<=2 initially; absent APIs select1 Worker/128MiB. Manual1..4 uses coordinator128/256MiB and64MiB helpers under a512MiB stage ceiling. Adding Workers never multiplies the global transport budget:32MiB reserves four8MiB packets. Roles, module caps, protocol identities and finite deadlines are checked before/after dispatch as applicable.

Reuse Stage18 native sources and preserve every original artifact/evidence. Rebuild only memory maximum variants with exact source pins and two clean builds. No mathematical parameter, LP coupling, family selection or proof strength changes. Higher counts must prove packet/counter equality and pass the preregistered paired yield gate. Count changes are measured independently of geometry or other algorithm changes.

Keep requested/configured/observed memory separate. Resource failure is incomplete, not a prime/factor proof. Cancellation and uncertain retirement cannot admit another overlapping job. Never probe capacity by huge allocations; no automatic fresh-budget retry. Device-dependent high-difficulty limits are acceptable, but do not imply unlimited CPU/RAM use.

Larger total budgets, automatic3/4 adoption, alternate coordinator scheduling and physical-phone defaults need their own evidence and explicit finite policy. No external dependency, site deployment or public entry is added by this decision.
